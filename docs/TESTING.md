# Проверки и критерии приёмки

## Статические

```bash
python -m compileall -q src
python -m unittest discover -s tests -v
python src/scope_anchor.py check examples/complete-task.md --json
python src/scope_anchor.py compile examples/complete-task.md
```

- Парсер распознаёт 11 точных полей, запрещает дубликаты/пустые обязательные значения.
- `new` не перезаписывает существующий файл; не создаёт лишние каталоги.
- `lock`/`unlock` меняют только явно заданный JSON, не позволяют подменять ключи и корректно работают с Unicode.
- CLI проходит стандартные модульные тесты без сети на Linux и Windows; для файлов используется `pathlib`.
- Запуск `compile` с неполным контрактом возвращает ненулевой код.

## Проверки после установки skill

В реальном Codex Desktop/CLI отдельно подтвердить: доступность `$scope-anchor`; срабатывание при явном запросе; отсутствие самовольного переключения модели/создания PR; продолжение работы до критериев приёмки; отсутствие лишних файлов. Эти наблюдения **не заменяются** тестами парсера и пока `NOT_VERIFIED`.

## KPI

Сравнивать две сопоставимые реальные задачи по `принятая задача / доля недельного лимита` и числу исправляющих ходов. Без снятых измерений нельзя заявлять об экономии. Логи должны содержать только время, версии, команду, код возврата и результаты, без секретов и содержимого пользовательских проектов.
