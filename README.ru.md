# ScopeAnchor

**Нативный skill для Codex: структурированные инженерные задачи, воспроизводимые процессы и разумное использование квоты.** ScopeAnchor превращает сложный запрос в ограниченный контракт исполнения, оставляя фактическую работу Codex.

**Версия:** 0.0.1 · **Лицензия:** MIT · **Среда:** Python 3.10+ для необязательного CLI; самому skill Python не нужен.

## Возможности

- Помогает Codex сначала изучить инструкции репозитория и его текущее состояние.
- Проверяет запросы на повторы и противоречия, отсутствие критериев приёмки, неопределённый стек/runtime, лишний контекст и необоснованное расширение объёма.
- Явно фиксирует цель, объём, исключения, ограничения, критерии приёмки, условие остановки и формат отчёта.
- Сохраняет решения как справочный контекст, неизвестные факты помечает как неизвестные.
- Рекомендует минимально достаточную модель и усилие рассуждения; не переключает выбранную пользователем модель и не меняет настройки Codex.
- Предоставляет офлайн CLI для создания, проверки и компиляции контрактов задач и управления локальными решениями.
- Хранит персональные решения в `.scope-anchor/`, исключённой из Git по умолчанию.

Основной интерфейс — skill. CLI необязателен и не запускает Codex, модель, shell-команды или сетевые службы.

Для обычной многошаговой разработки рекомендация по умолчанию — GPT-6 Luna Medium; Low подходит для простых редакторских или механических изменений, а High требует конкретного обоснования сложностью или ценой ошибки. Это рекомендация: она не определяет и не переключает модель, выбранную в Codex.

## Быстрый старт

Установите skill в проект, скопировав `.agents/skills/scope-anchor/` в каталог `.agents/skills/` целевого проекта. Перед обновлением изучите существующую папку, не перезаписывайте настроенный skill вслепую. В Codex попросите:

```text
Используй $scope-anchor для выполнения задачи: <задача>
```

Codex обнаруживает проектные skills в `.agents/skills/`. Skill можно прочитать и применить вручную; установка не требует изменения глобальных настроек Codex.

## Необязательный CLI

Запускайте из корня репозитория с Python 3.10 или новее:

```console
python src/scope_anchor.py --help
python src/scope_anchor.py new --out TASK.md --goal "Исправить регрессию экспорта"
python src/scope_anchor.py check TASK.md --json
python src/scope_anchor.py compile TASK.md
```

`new` создаёт намеренно незаполненный шаблон с маркерами `TODO` и отказывается перезаписывать файл. Заполните обязательные разделы до `check` или `compile`. `compile` печатает проверенный контракт в стандартный вывод и ничего не сохраняет и не отправляет.

Локальное решение (не сохраняйте секреты):

```console
python src/scope_anchor.py lock --file .scope-anchor/decisions.json --key ui.window --value "Использовать одно окно"
python src/scope_anchor.py decisions --file .scope-anchor/decisions.json
python src/scope_anchor.py unlock --file .scope-anchor/decisions.json --key ui.window
```

Для намеренного изменения существующего ключа используйте `--replace`. Команды читают или меняют только явно указанные пути. Примеры для Windows и Ubuntu приведены в [руководстве по использованию](docs/ru/usage.md).

## Установка и разработка

Установка пакета и сторонние зависимости Python не нужны. В Windows используйте PowerShell и `py -3` или `python`; в Ubuntu — `python3`. Для самого skill достаточно, чтобы Codex мог читать файлы. См. [установку](docs/ru/installation.md) и [разработку](docs/ru/development.md).

## Архитектура и ограничения

ScopeAnchor состоит из нативного `SKILL.md`, небольших справочных документов, офлайн CLI на стандартной библиотеке Python и тестов. Здесь нет AI-шлюза, сервера, веб-интерфейса, базы данных, телеметрии или автоматической публикации. CLI проверяет структуру и отдельные свойства безопасности, но сам не доказывает правильность задачи, не разрешает семантические противоречия и не гарантирует успешное исполнение. Рекомендации по модели носят справочный характер. Экономия токенов и автоматическое обнаружение skill не измерялись и не гарантируются.

Канонический язык документации — английский. Парные русские документы обновляются в том же изменении и сверяются на эквивалентность требований, примеров и утверждений о статусе. См. [архитектуру](docs/ru/architecture.md), [безопасность](SECURITY.ru.md) и [происхождение](docs/PROVENANCE.md).
