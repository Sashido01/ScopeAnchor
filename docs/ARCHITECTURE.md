# Архитектура

## Статические компоненты

- `.agents/skills/scope-anchor/SKILL.md` — нативная точка входа Codex, краткий алгоритм и точные триггеры.
- `references/` — детальные правила, открываются только когда релевантны.
- `src/scope_anchor.py` — необязательный офлайн Python CLI для подготовки и проверки контрактов.
- `.scope-anchor/decisions.json` — локальные настройки, **не создаются автоматически**, игнорируются Git.
- `tests/` и CI — проверка детерминированного поведения, не симуляция запуска модели.

## Поток

Пользователь → Codex читает метаданные skill → при необходимости загружает `SKILL.md` → применяет существующие инструкции проекта → анализирует конкретные файлы → выполняет работу → подтверждает результат. Вручную можно создать `TASK.md`, проверить и компилировать CLI; CLI не запускает Codex и не вызывает внешние сервисы.

## Политика данных

CLI читает только явные аргументы пути. Создаёт файлы только по `new --out`, `lock --file`, `unlock --file`. `check`, `compile` и `decisions` — операции чтения. Никакого поиска токенов, телеметрии, удалённых API, автоматических изменений Global/Repo AGENTS.md. Секреты, журналы и пользовательские решения не коммитятся.

## Почему не сервис

Никакого FastAPI, Docker, процесса-наблюдателя, SQLite или собственного оркестратора задач: Codex уже является исполнителем, навыку нужен контракт, а не конкурентный runtime.
