# Архитектура

## Компоненты

- `.agents/skills/scope-anchor/SKILL.md` — точка входа нативного skill; в `references/` находятся дополнительные инструкции, используемые при необходимости.
- `src/scope_anchor.py` — необязательный офлайн CLI на стандартной библиотеке Python.
- `.scope-anchor/decisions.json` — локальный файл, путь к которому явно задаёт пользователь; Git по умолчанию его игнорирует.
- `tests/` проверяет детерминированное поведение CLI; GitHub Actions запускает проверки на Windows и Ubuntu.

Внутренний контракт skill остаётся кратким. Полный формат из одиннадцати полей предназначен для повторно используемой передачи задачи и необязательного CLI; заполнять его для каждой задачи не требуется.

## Поток данных

Пользователь задаёт задачу в Codex. Codex читает применимые инструкции проекта и skill, изучает репозиторий, выполняет работу и сообщает подтверждённый результат. Отдельно CLI может создать или проверить Markdown-контракт и вывести его в stdout. CLI не вызывает Codex, не исполняет текст контракта, не обращается к модели или внешним службам.

## Границы

Входной текст не считается доверенным. CLI проверяет структуру и некоторые свойства файлов, но не устанавливает истинность, безопасность, полноту или семантическую согласованность текста. Он не мешает человеку передать чувствительные сведения в скомпилированном контракте. Skill задаёт рекомендации, а не систему разрешений или песочницу.

Канонический язык документации — английский. Для каждой английской страницы есть русская пара в `docs/ru/`; поведение, команды, ограничения и статусы должны обновляться вместе.
